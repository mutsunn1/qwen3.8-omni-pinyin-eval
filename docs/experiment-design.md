## 一、关键问题

- ✦ RQ1：Qwen3.8-Omni 能否直接从音频中识别声母、韵母和声调？
- ✦ RQ2：已知目标拼音后，模型能否准确完成目标文本—音频一致性检测？
- ✦ RQ3：模型对目标文本的依赖有多大？是否会把实际读错的发音自动纠正为目标发音？
- ✦ RQ4：不同音素类别与推理模式，会怎样影响模型的表现？

### 一般问题

- 推理强度是否影响识别效果？
- 对不同类别声母、韵母、声调识别性能是否存在差异

## 二、数据集构建

采用`mandarin_tone_syn`，该数据集使用Google Cloud TTS产出语音，包含`speaker`（使用的TTS），`target`（无调拼音），`label`（声调），使用时需先拆分声母韵母再做细分类。

理想形状为：

```json
{
  "target": "zhang",
  "target_initial": "zh",
  "target_final": "ang",
  "target_tone": 1
}
```

✦ 数据集说明：`mandarin_tone_syn` 共 6160 条、4 个 TTS voice（各 1540 条）、385 个原始 target（映射合并后 378 个）；`label` 为声调 1–4，四声各 1540 条，无轻声。`target` 采用规范化零声母写法：`in→yin`、`ing→ying`、`iu→you`、`u→wu`、`ui→wei`、`un→wen`、`ün→yun`；`target_initial`/`target_final` 按 `mandarin_tone_syn_target_mapping.csv` 查表，不在代码里硬编码规则。 数据来源：`HaitongSUN/prosodic-abx` 的 `mandarin_tone_syn` config，commit `d607806619aba678030dac10ea086fb19347205a`（[HuggingFace](https://huggingface.co/datasets/HaitongSUN/prosodic-abx)）。

## 三、实验设计

评估指标：✦

| 指标                          | 定义 / 用途       |
| --------------------------- | ------------- |
| Initial Accuracy / Macro-F1 | 声母识别          |
| Final Accuracy / Macro-F1   | 韵母识别          |
| Tone Accuracy / Macro-F1    | 声调识别          |
| Joint Accuracy              | 三个维度全部正确      |
| Error Precision (EP)        | TP/(TP+FP)，判为不一致中真正不一致的比例 |
| Error Recall (ER)           | TP/(TP+FN)，真正不一致被检出的比例 |
| Error F1                    | 2·EP·ER/(EP+ER)，误报与漏报的综合 |
| False Positive Rate (FPR)   | FP/(FP+TN)，一致样本被误判为不一致的比例 |
| False Negative Rate (FNR)   | FN/(FN+TP)=1−ER，不一致样本被漏判的比例 |
| Confusion Matrix            | 具体哪些音素容易混淆    |

✦ 其中 TP：实际不一致且判为不一致；FP：实际一致但判为不一致；TN：实际一致且判为一致；FN：实际不一致但判为一致。判定阈值 τ：模型输出概率时取 τ=0.5（本项目无 dev 集，固定 0.5）；只输出文本时，以明确的“不一致/错误”标记为阳性；输出无法解析或拒答时，单独记为失败并报告比例。

✦ 实验 × 指标矩阵（✓ 表示该实验计算该指标，— 表示不适用）：

| 实验/任务 | Initial | Final | Tone | Joint | EP/ER/F1 | FPR/FNR | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 实验一 | — | — | ✓ | — | — | — | 正确目标；只评声调 |
| 实验二 | — | — | ✓ | — | — | — | 错误无调拼音；只评声调 |
| 检测实验 | — | — | — | — | ✓ | ✓ | target+target_tone；2/2/1 错误 |
| 实验三 | ✓ | ✓ | ✓ | ✓ | — | — | 无参考自由识别 |
| 实验四 | ✓ | — | — | — | — | — | 声母最小对 |
| 实验五 | — | ✓ | — | — | — | — | 韵母最小对 |
| 实验六 | — | — | ✓ | — | — | — | 声调最小对 |
| 消融 | 同对应实验 | 同对应实验 | 同对应实验 | 同对应实验 | 同检测任务 | 同检测任务 | 在基准上逐项变化 |

✦ 检测集构建：主分析按音频配平——每个音频取检测实验的 1 个一致样本（负类）和按 2 改声母 / 2 改韵母 / 1 改声调分层随机取 1 个不一致样本（正类），得到 6160 负类 + 6160 正类。另按错误类型分别构建 initial / final / tone 三个平衡子集（每类 6160 正类 + 6160 负类）。所有检测指标按音频聚类计算，检测实验的 5 个变体不视为独立样本。

✦ 统计方案：准确率、Macro-F1、EP/ER/F1、FPR/FNR 均报告 95% bootstrap 置信区间；bootstrap 以 audio 为聚类单位（同一音频的 5 个变体一起重采样），voice 作为分层变量。同一批音频的条件比较用 McNemar 检验；多条件/多次比较用 Holm 或 BH 校正；同时报告效应量（准确率差、风险差）。

✦ 基线：报告随机基线与多数类基线——声调四分类 25%，A/B 二选一 50%，平衡检测集 50%；声母/韵母按类别分布计算多数类基线。模型准确率需与这些基线一起解释。

✦ 评估设置：zero-shot，不训练、不提供示例；4 个 TTS voice（ZH_TTS_A/B/C/D）全量评估，并分别报告每个 voice 与总体；数据集只有 train split，因此不另做 train/test 划分；判定阈值 τ 固定 0.5，不做 dev 调参。

### 实验一

在原数据集上测试，给定正确的无调目标拼音，要求模型给出音频的真实声调。测试在给定无调拼音信息下的声调识别

### 实验二

在原数据集上测试，给定错误目标拼音，要求模型给出音频的真实声调。测试在给定错误拼音信息下的声调识别。

✦ 错误注入：每个样本构造 5 个错误无调拼音（只改声母或韵母，不含改声调；声调错误由检测实验覆盖）；正确答案以音频的真实声调为准，不采用目标拼音。5 个变体共用同一音频，统计时按音频聚类，不视为 5 个独立样本。

### 实验三

在原数据集上测试，不给定任何关于给定音频的读音信息，要求模型返回无调拼音和声调，测试模型自由评测的能力

### 检测实验

✦ 检测实验：给定 `target`（无调拼音）和 `target_tone`（1–4），要求模型判断目标拼音与声调是否与音频一致；不一致样本按 2 改声母 / 2 改韵母 / 1 改声调注入，一致样本使用原始 target 和 label。该实验用于 RQ2 与检测指标。

### 实验四

在清洗好的数据集上测试，测试同韵母同声调的声母最小对立组

### 实验五

在清洗好的数据集上测试，测试同声母同声调的韵母最小对立组

### 实验六

在清洗好的数据集上测试，测试同声母同韵母的声调最小对立组

最小对立组：✦

| 维度    | 对立组                  |
| ----- | -------------------- |
| 平翘舌   | z/zh、c/ch、s/sh（排除 zhi/zi 等 -i 组） |
| 送气    | b/p、d/t、g/k、j/q      |
| 鼻音/边音 | n/l |
| 前后鼻音韵母 | 所有声母的 -n/-ng 对（如 an/ang、en/eng、in/ing） |
| 其他韵母  | i/ü、ian/üan（控制声母环境）  |
| 声调    | 1/2、1/3、1/4、2/3、2/4、3/4 |

✦ 最小对配对规则：实验四固定同一 TTS voice、同一韵母、同一声调，只改变声母；实验五固定同一 TTS voice、同一声母、同一声调，只改变韵母；实验六固定同一 TTS voice、同一声母、同一韵母，只改变声调。两侧都必须存在于清洗后的数据中；平翘舌排除 `-i` 组，`i/ü`、`ian/üan` 在同一声母内配对。记录每类最小对的对数及 voice/声调分布。

✦ 最小对计数（每个 canonical target 在每个 voice/tone 下取 1 条音频；平翘舌已排除 `-i` 组）：

| 类别 | 配对类型 | 实例数 |
| --- | ---: | ---: |
| 平翘舌 | 36 | 576 |
| 送气 | 67 | 1072 |
| n/l | 21 | 336 |
| 前后鼻（所有声母） | 40 | 640 |
| i/ü | 5 | 80 |
| ian/üan | 3 | 48 |
| 声调 | 2268 | 9072 |

i/ü 与 ian/üan 类型最少，细分到 voice/tone 后需注意统计功效；声调对可按需抽样。

## 四、实验参数和消融设计

✦ 采用全因子设计：提示条件在实验一～三为 3 水平（自由识别 / 正确目标 / 错误目标），在实验四～六为 4 水平（增加 A/B 辨别）；Thinking、音频质量、输出形式均为 2 水平。实验一～三共 3×2×2×2 = 24 个条件，实验四～六共 4×2×2×2 = 32 个条件；除被消融变量外，固定模型版本、音频预处理流程和生成参数。

✦ 固定参数：模型使用阿里百炼提供的 Qwen3.8-Omni（固定模型 ID/版本与调用日期，记录在附录）；音频保持原始单声道 16 kHz/16-bit，除白噪声外不做重采样/增益；解码固定 temperature=0、top_p=1、max_output_tokens=256。

| 变量       | 实验条件                 |
| -------- | -------------------- |
| 提示条件 | 自由识别 / 目标条件（正确目标）/ 目标条件（错误目标）/ A/B 辨别（仅实验四～六） |
| Thinking | 开 / 关 |
| 音频质量 | 干净 / 加性白噪声（SNR 20 dB） |
| 输出形式 | 自由文本 / JSON |

✦ A/B 辨别（仅实验四～六）：给一段音频和两个候选拼音（一个正确、一个为同韵母/同声母/同声调的最小对立项），要求模型选择正确项；准确率按二选一计算，随机基线 50%，与一致/不一致任务分开报告。

✦ 输出与评分：JSON 模式要求只输出一个对象——实验一/二声调任务 `{"tone": 1-4}`，自由识别 `{"initial": "...", "final": "...", "tone": 1-4}`，A/B 任务 `{"choice": "A"|"B"}`，检测实验 `{"consistent": true|false}`。自由文本模式必须含 `声调=...`、`声母=...`、`韵母=...`、`选择=A/B`、`一致=是/否` 等固定标记，由程序按固定规则抽取。两种格式都先规范化（`ü/v/u`、`y/w`、大小写、声调数字），再与金标严格匹配；无法解析、拒答或多答案记为错误，并单独报告解析失败率。

✦ 样本量：主实验使用全量数据；消融每个条件 256 条，按 4 voice × 4 tone × 16 分层。实验四～六按最小对池抽样，池子不足 256 的类别（i/ü 80、ian/üan 48）使用全部可用对。每个条件固定同一子集，便于配对比较。

## 五、Prompt 模板

✦ 以下为各实验的 prompt 模板；`{...}` 为变量，音频随请求传入。Thinking 开关通过 API 参数控制，音频质量通过预处理/加噪控制，不改 prompt 文本。

### 共用 system prompt

```text
你是一个普通话单音节发音评估助手。请根据音频和用户给出的信息完成任务，
不要解释，不要输出思考过程，只输出指定格式的最终答案。
```

### 格式指令

**JSON 模式**

```text
只输出一个 JSON 对象，不要使用 Markdown 代码块，不要添加任何解释。
```

**自由文本模式**

```text
只输出一行，使用指定的固定标记，不要添加解释。
```

### 实验一 / 实验二

> 两个实验共用同一个 prompt；实验一用正确 target，实验二用错误 target。prompt 不提示 target 是错的。

```text
音频：一段普通话单音节。
目标拼音（无调）：{target}

请给出该音节的声调（1–4）。
{format_instruction}
```

- JSON：`{"tone": 1|2|3|4}`
- 自由文本：`声调=1`

### 实验三

```text
音频：一段普通话单音节。
请识别该音节的声母、韵母和声调（1–4）。
零声母用空字符串表示。
{format_instruction}
```

- JSON：`{"initial": "...", "final": "...", "tone": 1|2|3|4}`
- 自由文本：`声母=zh；韵母=ang；声调=1`
- 零声母自由文本写 `声母=`

### 实验四 / 五 / 六

> 实验四：同韵母同声调，只改声母。实验五：同声母同声调，只改韵母。实验六：同声母同韵母，只改声调。A/B 顺序在实验代码中随机平衡。

```text
音频：一段普通话单音节。
候选 A：{candidate_a}
候选 B：{candidate_b}

两个候选只有一个音素或声调不同。请选择与音频实际发音一致的候选。
{format_instruction}
```

- JSON：`{"choice": "A"|"B"}`
- 自由文本：`选择=A`
- 候选格式：带调拼音，如 `zhang1`、`zang1`

### 检测实验

```text
音频：一段普通话单音节。
目标拼音：{target}
目标声调：{target_tone}

请判断目标拼音和声调是否与音频中的实际发音一致。
{format_instruction}
```

- JSON：`{"consistent": true|false}`
- 自由文本：`一致=是` 或 `一致=否`
- 错误注入：2 改声母、2 改韵母、1 改声调；prompt 不提示目标是否正确。

### 变量

| 变量 | 内容 |
| --- | --- |
| `{target}` | 无调、规范化拼音，如 `zhang`、`wei`、`ü` |
| `{target_tone}` | 1–4，无轻声 |
| `{candidate_a/b}` | 带调拼音，如 `zhang1`、`zang1` |
| `{format_instruction}` | JSON 或自由文本的格式指令 |
